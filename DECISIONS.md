# DECISIONS

Формат: **решение** — альтернативы — почему.

## Правила (флаги в rules.yaml)
1. **Джокер = 7♠, одна карта** (флаг `deck.jokers`, поддерживаются 0..2 джокера, напр. `["6S"]`). — 6♠, два джокера как в грузинском Joker. — Википедия/поиск: 7♠ «один из распространённых вариантов», совпадает с ТЗ.
2. **Расписание**: 1..max−1, затем `max_repeats`(=n) раздач по max, затем max−1..1, затем n бескозырок и n тёмных по max. Для 4 игроков: 28 раздач. — буквальное чтение «1..max, затем N по max» дало бы N+1 раздачу по max. — Выбрано, чтобы каждый игрок ровно один раз сдавал максимальную раздачу (симметрия по позициям). Всё настраивается.
3. **Козырь**: следующая карта колоды после раздачи; джокер или пустая колода → бескозырка. Следствие: при 4 игроках все раздачи по 9 карт — бескозырные (колода роздана полностью). Вариант `trump.no_cards_left: dealer_last` (козырь по последней карте сдающего) реализован.
4. **Правило сдающего** (hook) включено флагом `bidding.dealer_hook`. Всегда остаётся ≥1 легальный заказ (n_cards ≥ 1 → минимум 2 значения).
5. **Тёмная**: заказ до просмотра своих карт (Obs.hand = 0 в фазе заказа), открытый козырь виден (`dark_sees_trump`), очки ×2 (и плюс, и минус).
6. **Джокер**: может быть сыгран в любой момент (`joker_any_time`). Не заходя: «старший» (бьёт всё) или «младший» (никогда не берёт). Заходя: всегда называется масть X и старший/младший.
   - заход «старший X» с флагом `joker_lead_demand_highest` (по умолчанию ВКЛ): остальные обязаны дать старшую карту X, нет X → козырь, нет козыря → любая; джокер берёт взятку. Это стандартное «по старшим пикам», а «по старшим козырям» = вызов козырной масти.
   - заход «младший X» (`joker_lead_low`): джокер = младшая карта масти X; ход в X обычный; взятку берёт старшая X или козырь; если никто не дал X/козырь — джокер берёт (как описано в источниках).
   - с двумя джокерами поздний «старший» бьёт ранний.
7. **Очки**: ровно → 10×заказ, пас выполнен → 5, перебор → 1 за лишнюю, недобор → −10×заказ (`under_mode: bid`; альтернатива `missing` = −10×недостача). Тёмная ×2.
8. Не реализовано (сознательно): «после двух пасов подряд обязан заказывать», премии за «пульку»/все выполненные заказы, штрафы за ренонс (движок не допускает нелегальных ходов). Записано в README как варианты.

## Архитектура
9. **Python 3.13 (в контейнере), чистый Python движок на битмасках** — numba/Cython. — Сырой движок ~10k раздач по 9 карт/с (~400k действий/с): достаточно; узкое место будет в агентах (PIMC, NN).
10. **Единое пространство действий 59 id** (36 карт + 10 вариантов джокера + 13 заказов). — раздельные пространства для фаз. — Проще маски и NN-голова; фазы отличаются маской.
11. **Агенты получают Obs** (без чужих рук; тёмная прячет руку). Эвристика написана на общих полях State/Obs, чтобы в роллаутах PIMC работать без построения Obs (скорость).
12. **Цель агента = собственные очки за раздачу** (EV). — максимизация разницы с соперниками / вероятности победы в партии. — Игра general-sum на 4 игроков; EV собственных очков — естественная «объективная» метрика и даёт аддитивность по раздачам; все инсайды формулируются в очках за раздачу.
13. **Duplicate-метрика «vs field»**: кандидат по очереди в каждом из 4 мест против 3×field, сравнение с партией 4×field на тех же сидах; Δ в очках на раздачу. — классические турниры случайными раскладами. — Убирает дисперсию раскладов (CI ≈ ±0.4 очк/раздачу на 100 партиях). Плюс pairwise ABAB/BABA → Bradley–Terry Elo.
14. **OpenSpiel-обёртка не сделана** (pyspiel не установлен, тратить время на сборку нецелесообразно); AEC-подобный API без зависимости от pettingzoo.
15. **По замечанию пользователя: соперники не должны быть «донорами» очков.** Добавлен `heuristic2` (агент «сильный клубный игрок»: EV-оптимальный заказ с учётом асимметрии очков и чужих заказов, точная 1-карточная политика, память карт/мастер-карты, аккуратный джокер): +1.96 очк/раздачу против `heuristic`. Основные поля для оценки теперь `heuristic2` и self-play/PIMC; `heuristic` оставлен как модель «типичного человека».
16. **Раздельные модели заказа и розыгрыша** (`train.dmc --separate`): bid-сеть видит руку, позицию, козырь, n_cards, уже сделанные заказы; play-сеть — всё, включая заказы всех. Заказ выбирается как argmax Q_bid(s, b) = E[очки | заказ b] при текущей политике розыгрыша — это ровно «argmax ожидаемых очков с учётом правила сдающего» (маска легальных заказов), но без промежуточной модели распределения взяток (её роль играет калибровочный анализ). — регрессия распределения взяток + argmax EV. — Q-оценка напрямую оптимизирует то, что нужно, и учитывает, что розыгрыш подстраивается под заказ.
17. **PIMC с роллаутами heuristic2** заметно сильнее PIMC с роллаутами heuristic (+4.2 против +2.0 vs поле heuristic2, 30 партий): качество политики роллаутов — главный рычаг PIMC.
18. **Контролируемые эксперименты (сдвиг заказа, политики джокера, тёмная, заход с туза) — на DMC-агентах**, а не на PIMC: duplicate по сотням раздач на размер и место требует ~10⁵ раздач; DMC в ~100 раз быстрее. Ключевые эффекты повторены на двух разных сетях (v1, v2) и сверены с PIMC self-play статистикой — где совпадают, помечено «надёжно».
19. **Салфеточная формула**: линейная оценка взяток (коэффициенты округлены из OLS по self-play сильных агентов) + сдвиг −0.4. — дерево решений, имитирующее заказы. — Деревья совпадают с заказами сети в 63–80%, но стоят −2…−2.5 очка/раздачу (ошибаются в дорогую сторону); формула стоит лишь −0.27.
20. **heuristic2c** (heuristic2 + OLS-калибровка из `agents/calib_default.json`) — «знающий человек»; используется и как политика роллаутов PIMC (`pimc_h2c`).
21. **v2/v3 обучены дообучением** (warm start) от v1/v2 с понижением lr (3e-4 → 1e-4 → 5e-5) и добавлением heuristic2 в пул соперников. Сравнение «раздельные сети vs одна сеть» поэтому смешано с эффектом дообучения/lr — честного A/B с нуля не делалось (не хватило бы CPU).
22. **Модель распределения взяток (train/bid_dist.py) реализована, но не выбрана для лучшего агента**: заказ по argmax EV под P(t|x,b) проигрывает Q-сети заказа −1.01 [−1.39, −0.62] очк/раздачу. Оставлена как компонент/бейзлайн (`store:biddist_v3`).
